# 附件经验的采用边界

随应用提供的本机 Z-Image 和 Qwen 生图资料只作为经验参考，不是当前机器或其他用户机器的安装收据。它们能减少排障绕路，但不能替代 `comfyui-local` 的环境探测、固定组件集、来源身份核对、会话审批策略和最小生成验证。完整计划提交 `action=request` 后，由应用读取实际审批模式：全自动模式直接启动，其他模式只需安装卡片的一次 UI 确认；不要另加聊天确认，也不能从提示词或环境变量推断授权。

## 已并入的通用做法

- 生成前读取选定 ComfyUI 实例的 `/system_stats`、`/queue`、`/object_info`，并检查实际 Python/Torch 设备；队列非空时等待，不清理或打断别人的任务。
- 先提交一张图片或一个短视频 smoke input，保存 `prompt_id`/`jobId`，从 `/history` 或任务结果读取真实输出文件；HTTP 成功、空历史或猜测输出文件名都不是完成证据。
- 显存不足时保存失败节点、原始参数、任务前后显存和原始日志。确认远端终态、队列空闲及运行/GPU身份后先释放并有界观察清理结果，再使用原模型、原参考和原参数最多重试一次；重试计数持久化。不得自动缩小尺寸、降低批量、画质或切换量化。第二次 OOM 停止并让用户选择新方案；提交/取消未确认或监控断线时恢复已有任务，不能重复提交。
- 分辨率会显著影响空间张量的峰值占用；减少采样步数通常主要改变耗时，不能把它当作降低峰值显存的可靠修复。不要在未核对队列时调用 `/free` 或释放其他工作流占用的资源。
- 单图任务逐张执行，记录实际执行时间和重试/等待时间；经验耗时只能标为本机测量，不能当作保证。
- 始终检查并使用目标 ComfyUI 自己的 Python/Torch 环境。已能运行的旧 GPU 组合不要无理由升级到更新 CUDA/Torch，也不要用另一实例的系统 Python 安装依赖。

## 明确不直接采用的内容

- 附件中的固定 Windows 根目录、端口、驱动版本、模型文件大小和启动命令不写入共享方案。它们必须通过当前机器的环境探测重新确认。
- 只有文件名和字节数的本机下载记录不能成为候选源；缺少固定仓库、revision、路径、许可证、SHA-256 和加载器证据时，仍停在可审阅计划。
- 不把附件脚本中的 `curl`/`uv pip` 或独立下载逻辑作为通用安装器。下载必须由已批准的 `openh3_comfy_install` 计划执行，并保留断点收据。
- 附件的 Qwen Image 2.1 Turbo 文生图组件不是 Qwen-Edit 编辑组件，不能因为都叫 Qwen 就复用编码器、VAE、LoRA 或工作流。附件的 Z-Image INT8 记录也只有在补齐来源身份、哈希、加载器和 smoke 证据后，才能登记为独立候选方案。

## 候选线索，不是推荐方案

- Z-Image 附件记录了 GTX 1080 8GB 上的 INT8-ConvRot diffusion、Qwen 3 4B FP8 mixed encoder、`ae.safetensors`、512 起步及 8-step 工作流线索。其文件字节数和 `hf-mirror.com` URL 不含足够的固定 revision/SHA-256 与本 Skill 当前候选记录；只能作为同类硬件的进一步调查线索，不能直接安装、登记或宣称已验证。
- Qwen 附件记录的是 Qwen Image 2.1 Turbo 的 INT8 diffusion、W4A8 encoder 和 BF16 VAE 文生图路径，不是 Qwen-Image-Edit。其本机耗时和 640/768 分辨率 OOM/成功结果只可作为该设备的运行记录；不能当作跨设备显存表、性能承诺或 Qwen-Edit 的量化推荐。
- 两个附件的生成脚本依赖已知的本机端口、loader 和文件名，且不完整处理已排队任务和来源收据；只复用其预检、单项验证和结果取证经验，不把脚本作为通用运行或安装接口。

## 网络来源

附件中的 `hf-mirror.com` 只能作为传输候选。先保留上游仓库和固定 revision 作为身份记录，再按 [network-and-downloads.md](network-and-downloads.md) 探测魔搭、可靠国内镜像和上游；可达、同名、同大小或 Range 成功均不能证明内容一致。
