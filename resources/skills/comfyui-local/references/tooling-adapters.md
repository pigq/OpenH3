# Reuse before inventing tooling

Use these upstream skills and references as narrow adapters. They reduce repeated troubleshooting without bypassing OpenH3's plan, consent, profile, and verification contract.

Consent means authorization under SKILL.md's observed approval-mode contract, not an additional chat-confirmation step: full automatic approval starts a valid submitted plan directly; other modes require one UI confirmation.

| Need                                                                    | Reuse                                                                                                                         | Boundary                                                                                                                                                                                             |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ComfyUI installation, workspace selection, pinned node/model operations | [`comfy`](https://github.com/Comfy-Org/comfy-cli/blob/main/comfy_cli/skills/comfy/SKILL.md) from `comfy-cli`                  | Confirm the installed CLI help and route locally; keep OpenH3's absolute paths, fixed revisions, source receipts, and consent.                                                                       |
| Read logs and classify node/runtime failures                            | [`comfy-debug`](https://github.com/Comfy-Org/comfy-cli/blob/main/comfy_cli/skills/comfy-debug/SKILL.md) from `comfy-cli`      | Use its diagnosis patterns, then make a bounded repair plan and snapshot before mutation.                                                                                                            |
| Custom-node discovery and compatibility checks                          | [`comfy-custom-nodes`](https://github.com/Comfy-Org/comfy-cli/tree/main/comfy_cli/skills/comfy-custom-nodes) from `comfy-cli` | Use it to identify node classes and pinned commits; keep installation, source probing, consent, and smoke validation in this skill.                                                                  |
| Reproducible ComfyUI environment recipes                                | [`comfy-build`](https://github.com/Comfy-Org/comfy-cli/tree/main/comfy_cli/skills/comfy-build) from `comfy-cli`               | Borrow its environment/build vocabulary when a separate Python environment is needed; do not let it choose an unpinned package index or bypass the local profile snapshot.                           |
| H3 component grouping and integrity checks                              | [`h3lite`](https://github.com/Rimagination/h3lite) practices                                                                  | Treat hardware examples as evidence only; do not turn them into a fixed VRAM table. Keep each H3 component set together.                                                                             |
| Image workflow structure and node bindings                              | [`workflow_templates`](https://github.com/Comfy-Org/workflow_templates)                                                       | Pin the template revision and convert UI JSON to an API graph before approval. Do not fetch a new template during generation.                                                                        |
| Reachability, proxy, Range, and content-length evidence                 | Built-in `openh3_comfy_environment` with `sources`                                                                            | Probe exact candidate URLs before approval. It is read-only and does not establish model identity; compare receipts and hashes before selecting a mirror.                                            |
| Multi-shot H3 story planning                                            | `comfy-director` from `comfy-cli` (optional)                                                                                  | Reuse only its shot/continuity planning vocabulary. Every shot still resolves to a registered H3 profile and a fixed local API graph; it must not install a cloud route or invent model files.       |
| Showing a workflow/result in chat                                       | `comfy-relay` from `comfy-cli` (optional)                                                                                     | The desktop app already owns result cards and artifact paths. Do not add a second relay or upload local assets; use this adapter only when an external agent explicitly needs a presentation format. |
| ModelScope/domestic mirror selection                                    | Local [source-resolution](source-resolution.md) playbook plus `openh3_comfy_environment`                                      | There is no safe generic mirror downloader. Probe, compare identity, resume with receipts, and require consent through the local install executor.                                                   |

Do not copy upstream skill files into this bundle or invent a second generic downloader. Add a new local helper only when the required behavior is deterministic, testable, and not already covered by the adapters above. In particular, a ModelScope or domestic-mirror helper may probe reachability and compare receipts, but it must not silently rewrite an approved URL or select a same-name file.

For a cold install, combine these adapters in this order: `comfy` for the pinned local workspace and command vocabulary, `comfy-custom-nodes` for node class and commit discovery, `comfy-build` only for an isolated reproducible runtime recipe, and `comfy-debug` after a real log or `/object_info` failure exists. Keep source probing, mirror identity checks, user consent, resumable receipts, and smoke validation in this Skill. `comfy-director` and `comfy-relay` are optional planning/presentation adapters, not installation paths. There is intentionally no separate generic ModelScope downloader: one would bypass the profile component set and make it too easy for the LLM to switch to a same-name or moving artifact.
