# Reuse before inventing tooling

Use these upstream skills and references as narrow adapters. Prefer OpenH3's managed installation; use the general-tool fallback only under SKILL.md's availability, existing-operation, and runtime-permission rules. Both routes preserve component identity and verification.

For a managed operation, the observed approval policy either starts the plan directly or requires one installation-card confirmation. General-tool fallback uses the actual runtime's normal tool approvals and existing grants. Neither route adds a separate chat-confirmation step.

## General-tool installation fallback

1. **Establish ownership and capability.** Recover any existing operation, download process, or ComfyUI prompt first. An active, awaiting-approval, or unknown task blocks a competing installer. A genuine missing tool/capability may use this route after the available startup refresh; a permission, source-access, hash, or device rejection may not. A backend `COMFY_TOOL_NOT_READY` code alone does not establish that no operation or partial installation exists.
2. **Plan and inspect the target.** Reuse context and completed probes. Record a short checklist with the live Plan/Todo tool when available, otherwise a local installation journal. Use permitted file/command tools to inspect configured or recent ComfyUI roots, OS, GPU/driver/architecture, available VRAM/RAM/disk, interpreter, and installed runtime. Do not scan entire disks. Missing target dependencies are installation work, not an unsupported-device diagnosis.
3. **Select and pin one complete set.** Read the relevant family and candidate/workflow records. Reuse the pinned API baseline when it matches the selected components. If an identity, hash, schema, or support fact is missing, continue bounded research with available read-only HTTP, browser, file, or command tools. Consult authoritative metadata/source rather than guessing. Only block the affected transfer if required evidence still cannot be established. Never use a locally calculated digest of an untrusted download as its own expected upstream digest.
4. **Resolve sources and authorize execution.** Apply [source resolution](source-resolution.md) using equivalent read-only HTTPS probes if `openh3_comfy_environment` is absent. Prefer ModelScope, a verified domestic mirror, then upstream, with identical revisions/size/SHA-256. Preserve actual runtime approvals and existing grants; do not manufacture a card, approval mode, token, or request context. Keep authentication material out of command arguments, logs, URLs, and receipts.
5. **Install and transfer.** Use a dedicated target directory and the target runtime's interpreter; preserve existing user files and isolate conflicting dependencies. Use available download/package tools with fixed versions, `.part` files, resume metadata, bounded network retries, and final size/SHA-256 checks. Resume only when the source identity and server Range response match the receipt. Choose bounded parallel transfers for independent files; avoid concurrent writers to a file, Python environment, or node directory. Serialize dependent setup and shared GPU work. For long transfers, use supported background-process monitoring and saved process IDs/logs, or bounded resumable chunks, instead of exceeding a tool's timeout. A timeout does not prove that a process stopped. A hash mismatch stops the affected transfer and is diagnosed, not retried through another unchecked URL.
6. **Validate actual execution.** Check loader/node schemas and the exact API graph, then run one representative image/edit/video smoke input through the available supported interface. If using the local ComfyUI HTTP API, first inspect its queue and running work, wait for idle, never clear another task, and retain the returned prompt ID before monitoring history/output. Unknown submission, cancellation, or monitoring state requires recovery, not another submission. Decode the output and check motion/audio when promised. Do not add an untracked OOM retry loop or silently lower original parameters.
7. **Keep an honest handoff.** Save the selected versions, target paths, expected hashes, receipts, completed/pending stages, process/prompt IDs, errors, and validation evidence in the installation journal without secrets. Resume by checking real files/processes/history. Do not invent OpenH3 operation/job IDs or edit its private database/profile registry. Discover/register/revalidate through supported interfaces when available; otherwise report the locally tested installation and the exact application-integration step still pending. Starting a process or downloading weights alone is not installation success.

## Optional adapters

| ComfyUI installation, workspace selection, pinned node/model operations | [`comfy`](https://github.com/Comfy-Org/comfy-cli/blob/main/comfy_cli/skills/comfy/SKILL.md) from `comfy-cli`                  | Confirm the installed CLI help and route locally; keep OpenH3's absolute paths, fixed revisions, source receipts, and consent.                                                                       |
| Read logs and classify node/runtime failures                            | [`comfy-debug`](https://github.com/Comfy-Org/comfy-cli/blob/main/comfy_cli/skills/comfy-debug/SKILL.md) from `comfy-cli`      | Use its diagnosis patterns, then make a bounded repair plan and snapshot before mutation.                                                                                                            |
| Custom-node discovery and compatibility checks                          | [`comfy-custom-nodes`](https://github.com/Comfy-Org/comfy-cli/tree/main/comfy_cli/skills/comfy-custom-nodes) from `comfy-cli` | Use it to identify node classes and pinned commits; keep installation, source probing, consent, and smoke validation in this skill.                                                                  |
| Reproducible ComfyUI environment recipes                                | [`comfy-build`](https://github.com/Comfy-Org/comfy-cli/tree/main/comfy_cli/skills/comfy-build) from `comfy-cli`               | Borrow its environment/build vocabulary when a separate Python environment is needed; do not let it choose an unpinned package index or bypass the local profile snapshot.                           |
| H3 component grouping and integrity checks                              | [`h3lite`](https://github.com/Rimagination/h3lite) practices                                                                  | Treat hardware examples as evidence only; do not turn them into a fixed VRAM table. Keep each H3 component set together.                                                                             |
| Image workflow structure and node bindings                              | [`workflow_templates`](https://github.com/Comfy-Org/workflow_templates)                                                       | Pin the template revision and convert UI JSON to an API graph before approval. Do not fetch a new template during generation.                                                                        |
| Reachability, proxy, Range, and content-length evidence                 | Built-in `openh3_comfy_environment` with `sources`, or equivalent permitted HTTPS probes in fallback                          | Probe exact candidate URLs. Read-only reachability does not establish model identity; compare receipts and hashes before selecting a mirror.                                                         |
| Multi-shot H3 story planning                                            | `comfy-director` from `comfy-cli` (optional)                                                                                  | Reuse only its shot/continuity planning vocabulary. Every shot still resolves to a registered H3 profile and a fixed local API graph; it must not install a cloud route or invent model files.       |
| Showing a workflow/result in chat                                       | `comfy-relay` from `comfy-cli` (optional)                                                                                     | The desktop app already owns result cards and artifact paths. Do not add a second relay or upload local assets; use this adapter only when an external agent explicitly needs a presentation format. |
| ModelScope/domestic mirror selection                                    | Local [source-resolution](source-resolution.md) playbook with the managed probe or permitted fallback tools                   | A downloader does not select identities for you. Probe, compare identity, resume with receipts, and preserve the actual runtime's approval policy.                                                   |

Do not copy upstream skill files into this bundle or run a competing downloader alongside an active managed operation. In fallback, reuse an available download tool or a small scoped helper when needed. A ModelScope or domestic-mirror helper must preserve the selected identity, approved sources, receipts, and checks; it must not silently rewrite an approved URL or select a same-name file.

For a cold install, use these adapters when available: `comfy` for the pinned local workspace and command vocabulary, `comfy-custom-nodes` for node class and commit discovery, `comfy-build` for an isolated reproducible runtime recipe, and `comfy-debug` after a real log or `/object_info` failure exists. Missing optional adapters do not block equivalent work with permitted general tools. Keep source probing, mirror identity checks, runtime approvals, resumable receipts, and smoke validation. `comfy-director` and `comfy-relay` are optional planning/presentation adapters.
